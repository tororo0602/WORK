2. T/H 補正不一致チェック

関数：detect_tool_offset_mismatch_findings(lines)。collect_program_findings から呼ばれ、種類 tool_offset_mismatch（警告）の Finding を返します。

判定の手順（ブロックごと）

  1. find_g361_line で G361 の行を探す。無ければこのブロックは対象外。
  2. extract_t_before_g36x で T 番号を取る。G361 と同じ行の T、無ければ G361 より前で一番近い T（G361 より後ろの T は次工具の準備なので使わない）。表示は先頭4桁（T2005）。
  3. extract_g43_h_list で H を集める。対象は G43 を含む行（G43.4 も含む）の H だけ。コメント、G65 の行、H0 は除外。
  4. H が1つも無い → 「G43のH補正なし」（G361 の行に出す）。
  5. H38 以下の H が2種類以上 → 「H補正が複数」（2種類目が出た行に出す）。
  6. T の3〜4桁目（下2桁）を期待値として、H38 以下で期待値と違う H → 「T/H補正不一致」（その G43 の行に出す）。
定数値意味
PERMANENT_TOOL_H_MIN39これ以上の H はパーマネント工具。不一致・複数どちらの判定からも外す

正規表現のポイント：G43 の判定は G43(?!\d)（G430 などと区別、G43.4 は通る）。H は H(\d+) を数値にして比べるので H05 と H5 は同じ扱いです。

新しい検出の種類を足すとき触る場所

T/H 補正不一致を足したときに触った場所です。種類を増やすときは同じところを全部触ってください。

場所内容

3. 補正コメント

計画：plan_offset_comments(lines)（画面に依存しない純粋な関数）。画面：NcCheckApp._open_offset_comment_preview。

書く内容

  • 対象は G361 があり、extract_g43_h_list で H が取れるブロック。
  • H は出た順に重複を除いて H{番号:02d} で並べる → (H10 H110)。パーマネントの H も書く。
  • block_radius_comp_codes で G41／G42 の使用を調べ（コメント・G65 行は除外）、あれば (G41)／(G42)／(G41/G42) を後ろに付ける。

書く場所

  1. N 行の次から、空行かコメント行が続く範囲を「見出し部」とする。
  2. 見出し部に既に自動コメントの行（OFFSET_COMMENT_RE に一致）があれば、内容が違うときだけ 置き換え（action="replace"）。同じなら何もしない。
  3. 無ければ 挿入（action="insert"）。挿入位置は、N 行にコメントがあれば N 行の後ろ、無ければ見出し部の最初のコメント行（工具名）の後ろ、それも無ければ N 行の後ろ。
OFFSET_COMMENT_RE = ^\(H\d+(?: H\d+)*\)(?:\(G4[12](?:/G4[12])?\))?$

extract_tool_name はこの書式の行を飛ばすので、自動コメントが工具名として表示されることはありません。

反映

  • 確認画面は ReplacementPreview(..., grouped=True)。行ごとのチェックで選べる。
  • 確定時、プレビューを開いた時点の全文（snapshot）と今の全文が違えば反映せず、もう一度押すよう案内する（途中で編集されたときの事故防止）。
  • 行番号の大きい方から順に挿入・置換し、前後に edit_separator() を入れて Undo 1回で戻るようにしている。
  • 反映後は行番号・色分けを更新し、_auto_rerun_check で再チェック。

4. 軌跡シミュレーター：G コードの解釈

関数：simulate_block(rows, mode="", spindle=1)。mode は detect_n_index_mode の結果（"TURN"／"MILL"）、spindle は spindle_of_block の結果（1／2）です。戻り値は SimResult（表示空間、Segment の一覧、注意書き、省略した本数、C 割り出しの有無、主軸側）。

モーダル状態

状態指令初期値
位置 X(直径)・Y・Z・CX／Y／Z／C（絶対）、U／V／W／H（インクリメンタル）Y=0、他は「不明」
移動の種類G0／G1／G2／G3G0
絶対・インクリメンタルG90／G91G90
平面G17／G18／G19旋削は G18、他は G17
極座標補間G112 開始、G113 解除（どちらも C を「不明」に戻す）解除
送りF、G98（毎分）／G99（毎回転）旋削は毎回転
回転数S、G96（周速一定）／G97、G50 S（回転数上限）—
固定サイクルG81〜G89 開始、G80 または G0〜G3 で解除なし

位置が「不明」の間は線を描きません。ブロックの最初、G28／G30／G53 で指定された軸、G361／G362（工具交換）、G112／G113 の C が「不明」になります。両端の位置が分かる移動だけを Segment にします。

読み飛ばす行と注意書き

行扱い
#、[、IF／GOTO／WHILE／DO／END「変数・マクロ文は描画しません」
G65／G66「G65/G66 マクロ呼び出しは描画しません」
G70〜G76「旋削固定サイクルは未対応です」
G43.4「G43.4（同時5軸）は未対応です」（行自体は処理を続ける）
G4（ドウェル）、G10、G11無視（G4 の X は時間なので座標として読まない）
G50 に X／Z座標系設定は反映せず、X・Z を「不明」に
G43／G43.4／G49 の行の H補正番号として扱う（それ以外の H は C のインクリメンタル）

表示空間（点の持ち方）

空間点図
SPACE_TURN（旋削）(Z, X/2, Y)Z–X
SPACE_MILL（ミーリング）(X/2, Y, Z)X–Y、X–Z
SPACE_POLAR（G112）(X/2, C, Z)　C は mmX–C、X–Z
SPACE_MILL_C（C 割り出し）(ワークX, ワークY, Z, 機械X/2)端面（0,1）、機械 X–Z（3,2）

X は常に直径値なので、点にするときに半分にします。ブロック内に G112 の区間があれば極座標の空間で表示し、G112 の外の移動は省略して「G112 の外の移動 N 本は省略」と出します。

円弧

平面ごとの軸と中心のワード（_arc_plane）：旋削は (Z, X) と (K, I)、G17 は (X, Y) と (I, J)、G18 は (Z, X) と (K, I)、G19 は (Y, Z) と (J, K)、極座標は (X, C) と (I, J)。I は半径値です（極座標の円弧で、始点・終点から中心までの距離が両方 29.9 になることで確認済み）。

  • I/J/K 指定：中心 = 始点 + (I, J, K)。始点と終点が同じなら一周。
  • R 指定（_r_center）：弦の長さを d として h = √(R² − (d/2)²)。中心 = 弦の中点 ± h ×（進行方向の左向き単位ベクトル）。反時計回り（G3）で R>0 なら＋、時計回り（G2）なら −、R<0（大円弧）は符号を反転。
  • 回転方向：横軸を右、縦軸を上にした図で G2 = 時計回り。旋削は仮決め
  • 描画用に 2°ごと（ARC_STEP_RAD）に分割。始点・終点は計算誤差が出ないよう元の座標をそのまま使う。

穴あけ固定サイクル（G81〜G89）

  • 穴の方向：G81〜G86 は Z、G87〜G89 は X（側面）。
  • 穴底：サイクル行の Z（または X）。以降の行で X／Y／C だけ指令されたら、同じ穴底で次の穴。
  • R 点 = 初期点 + R（X 方向は直径なので R×2）。仮決め
  • 描き方：(1) 穴位置へ早送り → (2) R 点へ早送り → (3) 穴底へ切削 → (4) 初期点へ早送り。ペックの往復は描かない。

C 軸割り出し

極座標補間の外で、0 以外の C が指令されたブロックは「C 割り出しあり」とし、ミーリングの点をワーク基準に回します（_rotate_by_c）。

θ = −radians(sign × C)          sign = C_SIGN（第二主軸なら −C_SIGN）
ワークX = x·cosθ − y·sinθ
ワークY = x·sinθ + y·cosθ       （x = 機械X/2, y = 機械Y）
  • 移動中に C が変わる（C を回しながら切削）場合は、移動距離に比例して C を補間し、2°ごとに分けて描く。
  • C_SIGN = 1.0 は「C＋でワークが反時計回り（端面を正面から見て）」の仮決め。仮決め
  • 注意書き「C軸割り出しをワーク基準で描画」は、この図で描いたときだけ出す（G112 前の割り出しには出さない）。

第二主軸

spindle_of_block(rows, previous)：M304／M203／M204／M245 があれば 2、M303 があれば 1。ブロック内に両方あれば後に出た方。どれも無ければ previous（前のブロック）を引き継ぐ。本体の _update_toolpath_now は先頭のブロックから順にこの判定をつないでいきます。引き継ぎは仮決め

表示の反転は view_flips(space, 図の番号, spindle) が返す（横, 縦）の符号で行い、点の値そのものは変えません。

図第二主軸での反転
旋削 Z–X横（Z）を反転
端面（X–Y、X–C、ワーク基準）横を反転（鏡写し）
X–Z（ミーリング・極座標・機械座標）縦（Z）を反転

再生の時間配分

重み（相対時間） = 移動の長さ ÷ 速さ
  早送り：速さ = RAPID_MM_MIN（20000、見た目用）
  毎分送り：速さ = F
  毎回転送り：速さ = F × 回転数
    回転数 = G97 なら S
           = G96 なら min(S×1000 ÷ (π×直径), G50 の上限)   直径は今の X（不明なら 50、最小 1）
  F が無いときは DEFAULT_FEED_MM_MIN（1000）
C が回る移動の長さ = √(直線の長さ² + (半径×回転角)²)

重みの合計を、1倍速で PLAY_SECONDS（20秒）になるように割り付けます。

5. 軌跡シミュレーター：画面

画面の切り替え

メイン画面の横並びは tk.PanedWindow（self._main_panes）です。

  • _enter_toolpath_mode：各ペインの minsize／stretch と実際の幅、境目（sash）の位置を保存 → NC プログラム以外のペインを forget → ToolpathPanel を add → 境目を全体幅 × TOOLPATH_PROGRAM_RATIO（0.30）に置く。
  • _exit_toolpath_mode：再生を止めて軌跡パネルを外し、保存した順番・幅で4ペインを足し直す。境目は _restore_sashes でその場と画面更新後の2回置き直す（PanedWindow が後から幅を詰め直すため）。
  • ツールバーの「軌跡」は _toggle_toolpath_mode。パネルの「✕ 閉じる」は on_close で _exit_toolpath_mode を呼ぶ。
  • マスコットはブロック情報パネルに付いているので、切り替え後に _refresh_mascot_position で位置を再計算（パネルが見えなければ自動で隠れる）。

ToolpathPanel

メソッド働き
set_block(label, rows, mode, spindle)(ラベル, 行, モード, 主軸側) が前回と同じなら何もしない。違えば解析して図を作り直し、再生位置とスライダーを最後にする
highlight_line(行番号)その行の移動を黄色の太線（点になる場合は丸）で重ねる
fit()全体表示。図を作り直す
toggle_play ／ _tick30ms ごとに時刻を進める
step_line(±1)前後の行の終わりの時刻へ移す
_nav(±1)再生を止めて on_block_nav（本体の _jump_n_block）を呼ぶ
_pick(番号)クリックした移動の行へ on_jump（本体の jump_to_input_line）
_redraw_dynamic工具位置の丸、途中までの線、通過済みの色、状態表示、エディタ追従を更新

PathView（1つの図）

画面X = ox + s × fa × 点[ia]
画面Y = oy − s × fb × 点[ib]      fa, fb = view_flips の符号
  • 全体表示：点の範囲が画面の 85% に収まる s と、中央に来る ox／oy を計算。縦横の縮尺は同じ。
  • ズーム・移動：Canvas の scale／move を "world" タグにかけ、s・ox・oy も同じだけ変える（図を作り直さないので大きなブロックでも速い）。
  • 色の切り替え：通過済みかどうかで色を変える。変わった範囲だけ塗り直す（_set_done）。
  • 大きさの目安：移動2万本のブロックで、作図約0.6秒、再生1コマ約7ms（Linux での計測）。

前の N／次の N

_jump_n_block(±1)：全ブロックの開始行の一覧から、カーソルを含むブロックを二分探索で求め、前後のブロックの開始行へ jump_to_input_line(行, align_top=True)。範囲外ならステータスバーに「先頭の N 番号です」「最後の N 番号です」。

8. 開発するときの注意

  • 改行コード：本体は CRLF と LF が混在（LF だけの行が27行）。全体を保存し直すと全行が差分になるので、変更行だけ触ること。
  • Windows 専用の部分：最大化（state("zoomed")）とマスコットの透過色（-transparentcolor）は Linux の Tk では動かない。Linux でテストするときは回避が要る（test_toolpath_layout.py 参照）。
  • 利用者データ：gm_glossary.json／nc_macros.json／macros/ はリポジトリに入れない。初期データを変えるときは GM_GLOSSARY_SEED／DEFAULT_NC_MACRO_TEXT を直す。
  • 版数付きのファイル名：版を上げるたびに _v40 などの名前を変える運用。並行作業ではリネームが衝突しやすい。
  • 新機能は別モジュールに：toolpath_sim.py のように本体から呼ぶだけにすると、本体（約1万行）を触る範囲が小さくて済む。
  • exe：会社の PC では exe がセキュリティで止められたため、Python のソースで運用中。
